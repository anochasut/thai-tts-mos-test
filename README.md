# Thai TTS AB Listening Test

An AB comparison test between one **Baseline** system and several **Candidate**
systems. Baseline/Candidate labels are shown openly (not blinded) -- only which
real system produced a given Candidate clip is hidden, behind an opaque token (see
`manifest.csv`); the real mapping is kept outside this repo.

Two parts, back to back:
1. **Comparison ("pair") trials**: for each rated utterance x each candidate,
   participants hear Baseline and Candidate, give a 1-5 AB preference score, rate
   the Candidate's naturalness, and transcribe the Candidate.
2. **Baseline-only ("solo") trials**, always last: participants rate and
   transcribe each Baseline clip on its own.

A practice pair (`demo_audio/` + `demo_meta.json`, not scored) is shown first so
participants know what to expect. English and Thai instructions are shown together
throughout.

Participants sign in with **Google** (Streamlit's native `st.login`, configured
under `[auth]` in the app's secrets -- see `../SETUP.md` step 4b). With no `[auth]`
section the app falls back to a local/dev mode that just asks for a typed-in email;
don't run a real study that way. Sign-in is what makes three things possible:

- **Resuming.** Each answer is uploaded as it's given, along with the participant's
  trial order, so they can stop any time and sign back in to continue where they
  left off -- same order, first unanswered trial.
- **Editing.** A Previous button and a Review page let them revisit any trial and
  change their answer; the re-saved file overwrites the original (flagged
  `"edited": true`).
- **Monitoring.** Emails listed in the `ADMIN_EMAILS` secret get a "Monitor
  participants" dashboard showing everyone's live progress.

Results go to a private Hugging Face **dataset** repo (`RESULTS_REPO_ID` +
`HF_TOKEN` secrets), laid out as:

```
{manifest_id}/{session_id}/_session.json          participant info + their trial order
{manifest_id}/{session_id}/{index:03d}_{utt}.json one file per answered trial
```

`manifest_id` is a hash of `manifest.csv`, so every regeneration of the test set
(every `prepare_manifest.py` run that changes the set) gets its own folder --
rounds never mix, and nobody can resume into a set that changed underneath them.
`session_id` is derived from the participant's email.

Secrets: see `.streamlit/secrets.toml.example` for the full template. The real
`.streamlit/secrets.toml` is gitignored -- never commit it.

`manifest.csv`, `audio/`, `demo_audio/`, and `demo_meta.json` are all generated by
`../prepare_manifest.py` -- don't hand-edit them; re-run that script instead (see
`../SETUP.md`, section 0) whenever the dataset or the included-utterance list changes.

Deployed on Streamlit Community Cloud. See `../SETUP.md` (in the parent project
folder) for deployment steps and `../analyze_results.py` for scoring (MOS + WER/CER
per system, plus AB preference per candidate).
